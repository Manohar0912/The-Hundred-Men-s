Live architecture

How this shareable version stays current.
1 · Scheduled refresh

GitHub Actions runs the updater every 10 minutes and on manual/push triggers.

2 · Validation guardrails

The ESPN batting refresh is rejected if it regresses below the current known leader threshold, preventing an old cached table from replacing newer data.

3 · Last-good fallback

If ESPN or Cricbuzz blocks a refresh, the previous verified JSON remains visible and the dashboard shows a warning.

4 · Browser polling

While the dashboard is open, it re-checks the published JSON every 60 seconds so a new deployment appears without a manual reload.

“Live” here means automatically refreshed published statistics, not ball-by-ball websocket scoring. GitHub Actions schedules are near-live and can occasionally run late. For true delivery-by-delivery production use, replace the scheduled scraper with a licensed cricket data API/backend while keeping the same dashboard UI and freshness controls.
